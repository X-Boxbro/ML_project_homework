================================================================================
超导临界温度回归 — 版本更新优化说明
================================================================================

本说明详细记录了从 train_v1.py 到 train_v9.py 共 9 个版本的实验演进过程，
涵盖架构设计、特征工程、超参数优化、元学习器和评估策略的逐步改进。

注意：文件命名 train_v1~v9 是按实验先后顺序排列，但各文件内部的 docstring
版本号（v3/v4/v5等）可能不一致，这是实验过程中对不同分支的标记约定。

关键评估指标（统一比较）：
- 数据集：17010 条超导材料样本
- 评估方式：8:1:1 Train/Val/Test（v3-v8）或 90/10 Train/Test（v9）
- 多种子（3 seeds）：[42, 123, 2026]
- 目标变换：自适应选择 log1p/sqrt/power
- SMOGN 提升：v1-v8 为 Tc>77K×1.5 倍，v9 改为 Tc>50K×2.0 倍


================================================================================
版本 1 — train_v1.py：「sklearn StackingRegressor + 原始空间训练」
================================================================================

【内部标识】Stacking Ensemble v4
【架构】XGB + LightGBM + CatBoost + ExtraTrees (4 个基模型) → RidgeCV/Lasso 元学习器

【主要特征】
- 使用 sklearn 内置的 StackingRegressor（而非自实现的手动堆叠）
- 在原始目标空间（未经 log/sqrt/power 变换）中训练，避免对数变换导致
  CV/HPO 评估不一致的问题
- 引入 ExtraTrees 作为第 4 个基学习器
- 添加了 20 个物理启发式特征工程（如 cv_、range_over_mean_、
  gm_over_am_、norm_entropy_、wtd_vs_mean_ 等比率特征，以及
  fie×ea、fie+ea、tc×dens 等交互特征）
- 特征选择：VarianceThreshold(0.001) + 高相关性剔除(corr_thresh=0.98)
- Optuna HPO：25 trials/模型，各模型独立搜索空间
- 无训练日志文件保存（使用默认 training_log.txt，未保留）

【与后续版本的差异】
- 无 SMOGN 增广（高 Tc 样本少的问题未处理）
- 无元素组成特征（仅使用 ml_train.csv 的统计特征）
- 无多种子集成
- 无 train/val/test 划分（仅 80/20 简单分割）
- 元学习器仅为 RidgeCV（无 BayesianRidge/ShallowRF/NNLS）
- HPO 仅在单 fold 上搜索（非 5-fold CV）

【此版本的地位】作为该实验系列的起点，验证了 sklearn StackingRegressor
在原始空间训练的基本可行性，但该路线在后续版本中被放弃，转而使用自实现的
变换空间堆叠方案。


================================================================================
版本 2 — train_v2.py：「空间统一的变换空间堆叠 + 多种子集成」
================================================================================

【内部标识】Stacking Ensemble v3 (Space-Unified)
【架构】XGB + LGB + CatBoost + ExtraTrees + Cubist (5 个基模型)
     → BayesianRidge + Ridge + ShallowRF(深度=3) 元学习器

【相对于 v1 的核心变更】

1. 训练架构重构：「空间统一」策略
   - 所有基模型和元学习器均在变换后的目标空间中训练
   - 仅在最终输出时进行一次逆变换
   - 解决了 v1 中原始空间训练的目标分布偏斜问题

2. 新增 Cubist 基学习器
   - 实现为 ExtraTrees + Ridge 的两阶段模型
   - ExtraTrees 先做粗预测，Ridge 对残差进行线性修正
   - 提供了与纯树模型互补的线性建模能力
   - HPO：n_estimators[100-500]、max_depth[5-25]、max_features[0.3-0.9]

3. SMOGN 启发的分层增强
   - 针对 Tc > 77.0K（物理上的高温超导阈值）的样本进行有放回采样
   - 对复制的样本加入高斯噪声（std = 0.5% × 特征值）
   - 增强比例：高温样本数 × 1.5 倍
   - 在 HPO 的 5-fold CV 每一 fold 和 Stacking CV 中均应用

4. 自适应目标变换选择
   - 比较 log1p、sqrt、Power(Yeo-Johnson) 三种变换
   - 使用 XGBoost(200 trees) 快速 5-fold CV 评估
   - 选择 RMSE 最低的变换方式

5. 非线性元学习器
   - BayesianRidge：贝叶斯岭回归，自动推断正则化强度
   - RidgeCV：对数空间搜索最佳 alpha[1e-4, 1e4]
   - ShallowRF(depth=3)：浅层随机森林，捕获基模型间的非线性交互
   - 若 top-2 元学习器 RMSE 相差 < 0.5%，则加权混合两者

6. 多种子集成 + Checkpoint 机制
   - 3 个随机种子 [42, 123, 2026]
   - 每个种子独立进行 HPO + CV + 重训练
   - 最终对 3 个种子的预测取平均作为集成结果
   - 引入 _checkpoint.pkl 断点续训机制

7. HPO 改进
   - 每个模型的 HPO 变为 5-fold CV（v1 是单 fold）
   - HPO 内部也应用 SMOGN（保持数据分布一致性）
   - SMOGN 的加入使得 HPO 搜寻到的参数更鲁棒

8. 特征选择阈值调整
   - corr_thresh 从 0.98 收紧至 0.92
   - 减少冗余特征，增强基模型间的多样性
   - 这一调整有利于堆叠（Stacking 要求基模型多样化）

9. 特征工程扩充
   - v2 在 v1 已有的 20+ 特征基础上新增了约 20 个特征：
     - fie×tc、ea×tc、fh×tc、ar×fh、fie×fh（热-电-机械交叉）
     - tc×val、dens×val、log_dens、sqrt_tc、sqrt_ar（非单调变换）
     - val_electron_density、packing_proxy（晶体结构代理量）
     - mc_llan_proxy（McMillan 公式的简化代理）
     - ea_over_tc、fh_over_ar、entropy_tc_product 等
     - fie_val_heterogeneity、fie_wtd_minus_mean（元素异质性）
     - tc_cv、dens_cv（变异系数）
     - val_tc_dens_3way（三因素交互）

10. HPO 缓存机制
    - hpo_cache/ 目录 + JSON 格式存储
    - 同一 transform + seed + model_name 组合可复用
    - 大幅减少重复实验时间


================================================================================
版本 3 — train_v3.py：「8:1:1 数据划分 + 防信息泄漏」
================================================================================

【内部标识】Stacking Ensemble v3 with 8:1:1 Split
【架构】与 v2 完全相同（5 基模型 + BayesianRidge/Ridge/ShallowRF）
【HPO】复用 hpo_cache/ 中的 v2 结果（同一特征空间，无需重新搜索）

【相对于 v2 的核心变更】

1. 引入标准化的 8:1:1 数据划分
   - Train: 80% (13608 样本) — 模型训练、HPO、CV
   - Val:   10% (1701 样本)  — 模型选择、集成方式决策
   - Test:  10% (1701 样本)  — 仅用于最终报告，不参与任何决策
   - 划分种子固定为 42，确保可复现

2. 消除信息泄漏（Data Leakage Prevention）
   - 特征选择（VarianceThreshold + Correlation）：仅在 Train 上拟合
   - 目标变换选择（PowerTransformer）：仅在 Train 上拟合
   - 对比 v2：v2 使用全部数据进行特征选择和变换拟合，导致 Val/Test
     信息泄漏到训练过程中

3. 以 Val RMSE 而非 Test RMSE 进行模型选择
   - 多种子集成 vs. 单种子 → 以 Val RMSE 为准决定
   - Test 仅用于最终报告的"无偏评估"

4. 独立日志文件
   - LOG_FILE = "training_log_v3.txt"（v2 使用默认 training_log.txt）
   - MODEL_PATH = "model_v3.pkl"

5. 新增 Gap 分析
   - 输出 Val-Train 和 Test-Val 的 RMSE 差距
   - 用于监测过拟合程度

【训练结果（v3 基线）】
- 集成 Test RMSE: 9.4681  MAE: 5.1052  R²: 0.9223
- Val-Train Gap: 5.4491（过拟合严重，Train RMSE=4.53, Val RMSE=9.97）
- 各单种子 Test RMSE: 9.39/9.51/9.55
- 总耗时：1272s（HPO 全部从缓存加载）


================================================================================
版本 4 — train_v4.py：「元素组成特征融合 + 移除 CatBoost」
================================================================================

【内部标识】Stacking Ensemble v4 (Element Fusion)
【架构】XGB + LGB + ExtraTrees + Cubist (4 基模型，CatBoost 被移除)
     → BayesianRidge + Ridge + ShallowRF(depth=3)

【相对于 v3 的核心变更】

1. 引入元素组成特征（来自 unique_m_train.csv）
   - 86 种化学元素的摩尔分数（稀疏矩阵）
   - 构建了约 30 个派生的元素级特征：
     - n_element_types：材料中实际出现的元素种类数
     - transition_metal_frac、rare_earth_frac：过渡金属/稀土元素比例
     - Cu/O/Fe/As/Se/Ba/Y/La/Sr/Nb/Bi_present（11 个关键元素指示变量）
     - is_cuprate/is_iron_based/is_bcuprates/is_rare_earth_based
       （4 种已知超导家族的标识特征）
     - tm_electron_proxy/re_electron_proxy（电子浓度代理量）
     - max_element_frac、element_concentration（主元素集中度）
     - element_entropy、element_entropy_norm（元素组成熵）
     - max/min_electroneg_in_material、electronegativity_spread
       （电负性差异）
   - 电负性查询字典：覆盖 H(2.20) ~ Rn(2.20) 共 86 个元素
   - 合并后总特征数：196（v3 原始 169 + 元素 27）

2. 移除 CatBoost 基学习器
   - 原因：CatBoost 在 HPO 中的 CV RMSE 为 10.37-10.59，远差于
     其他模型（9.44-9.64），拖累了堆叠性能
   - 从 5 模型降为 4 模型（XGB + LGB + ET + Cubist）
   - 减少元学习器的输入噪声，使权重分配更有效

3. 独立 HPO 缓存：hpo_cache_v4/
   - 新的特征空间需要重新搜索最优超参数
   - 但通过 enqueue_trial 将 v3 的参数注入 Optuna 作为 warm start
   - 加速收敛，避免从零开始搜索

4. 特征选择阈值放宽
   - corr_thresh 从 0.92 提升至 0.95
   - 理由：元素特征是稀疏的，过严的相关性过滤会丢失信号
   - 特征选择结果：196 → 153（v3: 169 → 126）

5. 最终重训练使用 best_iter + 10（v3 使用 +20）
   - 减少迭代数，降低过拟合风险

6. GPU 自动检测
   - 新增 _detect_gpu() 函数，通过 nvidia-smi 检测 CUDA 可用性
   - XGB 优先使用 GPU(cuda)，LGB 尝试 GPU(失败则回退 CPU)
   - CatBoost 已被移除，不再需要 GPU 配置

7. LightGBM 加入了 GPU fallback 容错
   - 若 GPU 不可用，自动切换为 CPU

【训练结果（v4 vs v3 对比）】
- 最佳单种子 Test RMSE: 9.0769 (vs v3: 9.3953) ↓ 0.32
- 集成 Test RMSE:     9.1275 (vs v3: 9.4681) ↓ 0.34
- Test R²:           0.9278 (vs v3: 0.9223)
- Val-Train Gap:     5.1330 (vs v3: 5.4491) ↓ 0.32，过拟合略有缓解
- 总耗时：4544s（vs v3: 1272s，HPO 重新搜索 + 元素特征计算）
- 最佳种子 2026 的 Test R² 为 0.9286（v3 为 0.9210），提升显著

【已知问题】
- 特征空间扩大后，HPO 搜索可能未能充分探索新的最优正则化区域
- 部分 V4 的 HPO RMSE 反而略高于 V3（如 XGB: 9.72 vs 9.57），
  提示需要调整搜索空间
- 代码末尾注明了"性能退化"和"边界触及"的风险诊断提示


================================================================================
版本 5 — train_v5.py：「HPO 正则化收紧 + 物理特征 + NNLS 元学习器」
================================================================================

【内部标识】Stacking Ensemble v5
【架构】XGB + LGB + ExtraTrees + Cubist (4 基模型，CatBoost 仍移除)
     → BayesianRidge + Ridge + NNLS (ShallowRF 移除)

【相对于 v4 的核心变更】

1. HPO 搜索空间收窄——强化正则化
   目的：解决 v4 中过拟合（Train-Val gap 大）的问题
   - XGB:
     * max_depth: [4, 10] → [3, 8]（限制树深度）
     * min_child_weight: [1, 7] → [3, 20]（增加叶子节点最小权重）
     * colsample_bytree: [0.3, 1.0] → [0.15, 0.8]（减少列采样）
     * reg_alpha: [1e-5, 30] → [1e-3, 100]（扩大 L1 范围）
     * reg_lambda: [1e-5, 30] → [1e-2, 200]（扩大 L2 范围，
       上限从 30→200 极大强化了正则化能力）
   - LightGBM:
     * num_leaves: [15, 127] → [15, 63]（减半最大叶子数）
     * min_child_samples: [3, 50] → [10, 80]（显著增加最小样本数）
     * colsample_bytree: [0.3, 1.0] → [0.15, 0.8]
     * reg_alpha/lambda: 同 XGB 收紧
   - ExtraTrees:
     * max_depth: [8, 40] → [8, 25]（砍掉过深的树）
     * min_samples_leaf: [1, 15] → [3, 30]（增加叶节点最小样本）
   - Cubist:
     * max_depth: [5, 25] → [4, 15]（大幅降低深度上限）

2. 新增物理启发式特征
   - Mendeleev Number（门捷列夫数）：
     * 使用 86 个元素的原子序数作为周期表位置代理
     * 计算加权平均值 mendeleev_mean 和加权方差 mendeleev_var
     * 反映材料的周期表位置分布
   - Valence Electron Concentration (VEC)：
     * 基于 Matthias 定则（超导 Tc 与价电子浓度关联）
     * 计算 vec_mean 和 vec_var
     * 各元素的价电子数来自物理参考数据

3. PCA 降维：稀疏元素列的 PCA 压缩
   - 对 unique_m_train.csv 中 86 列元素分数进行 PCA
   - 过滤：仅保留 ≥ 20 个非零样本的列（77/86 列通过）
   - 投影到 15 个主成分（解释 89.5% 方差）
   - 将 PCA 分量拼接到特征矩阵中
   - 处理后的训练特征数：172（157 原始 + 15 PCA）

4. 元学习器架构变更
   - 移除 ShallowRF(depth=3)：在 v4 中始终表现最差
   - 新增 NNLS（非负最小二乘）：
     * scipy.optimize.nnls 强制权重非负
     * 理论优势：防止基模型间的负权重（抵消效应）
     * 实际效果：v5 中 NNLS 的表现很差（RMSE≈40.7），远不及
       BayesianRidge/Ridge，未被选中为主元学习器

5. Cube 特征返回 elem_arr
   - build_element_features 新增返回原始 86 列分数矩阵
   - 用于后续的 PCA 计算
   - 配合索引分割（train/val/test 独立索引分配）

6. 独立 HPO 缓存：hpo_cache_v5/
   - 搜索空间变化，不兼容 v4 缓存
   - 不使用 warm start（参数空间完全不同）

【训练结果（v5 vs v4 对比）】
- 最佳单种子 Test RMSE: 9.0389 (vs v4: 9.0769) ↓ 0.04
- 集成 Test RMSE:     9.0321 (vs v4: 9.1275) ↓ 0.10
- Test R²:           0.9293 (vs v4: 0.9278)
- Val-Train Gap:     4.1295 (vs v4: 5.1330) ↓ 1.00 显著！
- 最佳种子 2026 Train RMSE: 5.25 (v4: 4.61)，Test RMSE: 9.04 (v4: 9.08)
- 总耗时：4504s

关键观察：Train RMSE 从 v4 的 ~4.6 上升到 v5 的 ~5.2（模型变"弱"了），
但 Test RMSE 从 9.08 降至 9.04。这证明收紧正则化成功减少了过拟合，
模型泛化能力提升。

NNLS 元学习器在变换空间中表现极差（RMSE≈40.7），可能是因为：变换后
的目标空间值分布使得非负约束下的最小二乘无法有效拟合。


================================================================================
版本 6 — train_v6.py：「CatBoost 回归 + 周期表位置特征 + HPO 扩展」
================================================================================

【内部标识】Stacking Ensemble v6
【架构】XGB + LGB + CatBoost + ExtraTrees (4 基模型，CatBoost 回归，Cubist 移除)
     → BayesianRidge + Ridge + NNLS

【相对于 v5 的核心变更】

1. CatBoost 恢复为基学习器（替代 Cubist）
   - 在 v4 中 CatBoost 因性能差被移除，但在 v6 中被重新引入
   - 与 v5 相比：用 CatBoost 替换 Cubist
   - HPO 参数：
     * learning_rate[0.01, 0.3]、depth[4, 10]
     * l2_leaf_reg[1.0, 100]（强正则化，范围比 v2 大幅扩大）
     * random_strength[0.5, 10]、bagging_temperature[0, 1.0]
   - GPU/CPU 自动适配 + fallback 容错

2. 新增周期表位置特征（Periodic Table Group & Period）
   - PERIODIC_TABLE 字典：86 个元素的 (族, 周期) 坐标
   - dom_group/dom_period：占比最大元素的族号和周期数
   - group_x_period：族 × 周期交互项
   - second_dom_frac：第二大元素的占比
   - 物理直觉：超导性质与最外层电子排布密切相关

3. HPO 搜索空间扩大
   - XGB:
     * max_depth: [3, 8] → [3, 12]（允许更深）
     * min_child_weight: [3, 20] → [1, 15]（放宽限制）
     * n_estimators: 400 → 600（更多轮次）
   - LGB:
     * num_leaves: [15, 63] → [15, 127]（恢复大范围）
     * n_estimators: 400 → 600
   - ET:
     * min_samples_leaf: [3, 30] → [3, 30]（不变）
     * n_estimators: 400 → 600
   - CatBoost: n_estimators 600, iterations 600
   - HPO trials: 25 → 35（更多搜索尝试）

4. NNLS 修复——在原始尺度上应用
   - v5 中 NNLS 在标准化后的 base_oof_s 上计算，导致 RMSE=40.7
   - v6 修复：NNLS 直接在 base_oof_t（原始 OOF 预测矩阵）上计算
   - 但修复后仍需 inverse_transform，实际效果仍不如 BayesianRidge/Ridge

5. 预测函数适配 NNLS
   - _predict_split 中的 _pred_for_meta 函数
   - 对 NNLS 类型的元模型，使用原始尺度矩阵（X_t）做矩阵乘法
   - 对其他类型，使用标准化后的矩阵（X_s）做 predict()

6. 独立 HPO 缓存：hpo_cache_v6/
   - 搜索空间和模型组合变化

【训练结果（v6 vs v5 对比）】
- 最佳单种子 Test RMSE: 9.0053 (vs v5: 9.0389) ↓ 0.03
- 集成 Test RMSE:     8.9807 (vs v5: 9.0321) ↓ 0.05
- Test R²:           0.9301 (vs v5: 0.9293)
- Val-Train Gap:     4.2975 (vs v5: 4.1295) ↑ 0.17，略有回升
- Seed 42 的 CV RMSE 异常为 33.90（BayesianRidge + NNLS blend 时
  NNLS 的预测崩溃），这是混合元学习器的权重混合 bug 导致的。

关键观察：
- CatBoost HPO RMSE 仍然很高（10.31-10.46），远逊于其他模型
- 但 4 模型堆叠的集成效果优于 v5
- 训练总耗时暴增至 31292s（~8.7 小时），主要是因为 CatBoost
  HPO 耗时极长（每个 seed 约 5800-7700s），占总时间约 60%
- 特征数 161 原始 + 15 PCA = 176

v6 的最大贡献是证明了：即使 CatBoost 单模型表现不佳，它在堆叠中的
互补性（与其他模型的相关性低）仍能提升集成效果。


================================================================================
版本 7 — train_v7.py：「5 模型 SLSQP 约束混合 + Debye/容差因子特征」
================================================================================

【内部标识】Stacking Ensemble v7
【架构】XGB + LGB + ExtraTrees + Cubist + CatBoost (5 基模型)
     → SLSQP 约束混合（替代 BayesianRidge/Ridge/NNLS）

   - v7 的 SLSQP 仅从均匀权重起点开始优化，可能陷入局部最优
   - v8 引入 3 个不同的初始权重向量：
     * 均匀起点：w_i = 1/n（与 v7 相同）

     * 随机起点：Dirichlet 分布生成的随机权重向量
   - 对 3 个起点分别运行 SLSQP，取目标函数最低的结果

     * OOF 预测更加稳定（更多验证 fold 平均）
     * SLSQP 元学习器基于更可靠的 OOF 估计来优化权重
     * 代价：每 fold 的训练样本增加但 fold 数翻倍，CV 总时间约翻倍
   - 日志显示 10 个 fold 的 Blend RMSE 波动更大（如 seed 42:

【相对于 v8 的核心变更】

1. 元学习器重构：XGBoost 非线性混合替代 SLSQP 线性混合
   这是 v9 最重要的架构变更。
   - v7-v8 使用 SLSQP 约束优化求解线性权重 w_i，最终预测 = Σ w_i × pred_i
   - v9 使用一个浅层 XGBoost 回归器作为元学习器：
     * n_estimators=100, max_depth=2（极浅，防止过拟合）
     * learning_rate=0.1
     * reg_alpha=1.0, reg_lambda=5.0（强 L1+L2 正则化）
     * subsample=0.8, colsample_bytree=0.8（行/列采样防过拟合）
   - 关键优势：
     * 非线性：XGBoost 可学习基模型预测之间的非线性交互关系
     * 自动特征选择：XGBoost 内建的树结构自动忽略不重要的基模型
     * 无需约束：树模型天然不存在负权重抵消问题
     * 更强表达力：depth=2 允许最多 4 个叶子节点，能捕获 pairwise
       基模型之间的条件依赖（如"当 XGB 预测高且 LGB 预测低时如何调整"）
   - SLSQP 的本质局限在于它只能做线性加权，而现实中基模型的误差
     往往是异质的（某些材料上 XGB 更准，另一些上 LGB 更准），
     非线性元学习器可以学会在不同区域依赖不同的基模型

     * v9 始终使用 3-seed 集成，不基于 Val 进行单种子 vs 集成的选择
     * 省出的 1701 个样本（从 Val 并入 Train）提供了更多训练数据
   - Train 集从 13608 增加到 15309，增加 12.5% 的样本

   - 代价：无法通过 Val 监控过拟合趋势，只能观察 Train-Test gap

3. 全模型在当前特征空间完整 HPO——不再是部分复用缓存
   v8 的策略：XGB/LGB/ET 从 v6 缓存加载（只需 15 trials 精调），

     验证了 v8 的"部分复用旧缓存"策略确实限制了 HPO 质量

2. XGBoost 元学习器的 Stack OOF RMSE 为 8.93-8.99（v8 SLSQP 为
   9.23-9.30），元学习器层面的提升约 0.3 RMSE。这证明了非线性
   元学习器相对于线性加权的显著优势。

3. 90/10 划分带来了更多训练数据，但也意味着无法像 v8 那样通过
   Val 监控过拟合。Test-Train gap = 4.04 需要通过与其他版本的
   相对比较来评估（v8 的 Test-Train gap 可通过 ensemble 结果
   推算为 8.94-4.75=4.19，v9 略优于 v8）。

4. SMOGN 阈值从 77K 降到 50K 后，更多中温超导样本（50-77K 区间）
   被增强。这个区间的样本可能对模型学习的贡献更大，因为这正是
   超导研究中最常见的温度区间。将增强比例提高到 2.0 进一步强化
   了中高温区域的信号。

5. IsotonicRegression 校准贡献虽小但稳定，验证了即使集成模型
   也存在轻微的系统性偏差。这种单变量保序回归不会引入过拟合，
   属于安全的"锦上添花"。

6. 时间成本：全模型 HPO 耗时增加但在可接受范围。XGB 25 trials
   约 450-824s，LGB 25 trials 约 890-1260s，ET 20 trials
   约 740-890s，Cubist 20 trials 约 690-870s。总计约 3 小时，
   相比 v6 的 8.7 小时仍然合理。

7. 架构收敛：经过 9 个版本的迭代，v9 的最优配置可以概括为：
   - 4 模型（XGB + LGB + ET + Cubist）→ XGBoost 非线性元学习器
   - 10-fold CV + 全模型在 178 维特征空间中完整 HPO
   - SMOGN: 50K 阈值 × 2.0 倍增强
   - 90/10 Train/Test 划分 + 3-seed 集成 + IsotonicRegression 校准
   - 这一配置在当前的树模型框架下可能接近性能上限

Test RMSE 从 9.40 降至 8.85，累计下降 5.9%。

1. 数据划分与评估（v1 → v9）
   - v1：简单 80/20 分割 → 不严谨
   - v3-v8：8:1:1 标准化划分 + Val 用于模型选择
   - v9：90/10 划分，移除 Val，固定 3-seed 集成，更多训练数据

2. 特征工程（v1 → v9，特征数 169 → 206 原始 / 178 最终）
   - v1：仅 ml_train.csv 的基础统计特征 + 简单比率
   - v2：大量物理交互特征（热电交叉、非线性变换）
   - v4：元素组成特征（86 元素分数 + 超导家族标识）
   - v5：Mendeleev 数 + VEC + 稀疏 PCA
   - v6：周期表 Group/Period 坐标
   - v7-v9：Debye 温度代理 + 容差因子（特征集稳定）

3. 基模型架构（v1 → v9）
   - v1：4 模型（XGB/LGB/CAT/ET）
   - v2：5 模型（+Cubist）
   - v4：4 模型（-CatBoost，因性能差）
   - v6：4 模型（+CatBoost 回归，-Cubist）
   - v7：5 模型（Cubist 回归，CatBoost 保留但被 SLSQP 清零）
   - v8-v9：4 模型（-CatBoost，已被多个版本验证不需要）
   - 最终共识：XGB + LGB + ET + Cubist 是经过 9 轮验证的最优组合

4. 元学习器（v1 → v9）——变化最大的维度
   - v1：sklearn StackingRegressor（RidgeCV，原始空间）
   - v2-v6：BayesianRidge/Ridge/ShallowRF/NNLS 竞争选择
   - v7：SLSQP 约束混合（线性加权 + 单起点）
   - v8：SLSQP 约束混合（线性加权 + 3 起点 multi-start）
   - v9：XGBoost 非线性元学习器（depth=2 树，突破线性加权的天花板）

5. 正则化与过拟合（v4 → v9）
   - v4：Train-Val gap = 5.13 → 严重过拟合
   - v5：收紧 HPO + 强正则化 → gap 降至 4.13
   - v7：gap 稳定在 4.24
   - v8：gap = 4.50 → 拓宽 HPO 后略有回升
   - v9：Test-Train gap ≈ 4.04（与 v8 的 Test-Train~4.19 相比更低）

6. SMOGN 策略演进（v1 → v9）
   - v1：无 SMOGN
   - v2-v8：阈值 77K，比例 1.5
   - v9：阈值 50K，比例 2.0（更激进的中高温区域增强）

7. CV 策略演进（v1 → v9）
   - v1-v2：5-fold
   - v3-v7：5-fold（在 Train split 内）
   - v8-v9：10-fold（在 v9 的 90% Train 集内，每 fold 更稳定）

8. 训练效率
   - v3：1272s（全缓存）
   - v6：31292s（CatBoost HPO 耗时巨大）
   - v7：2185s（复用缓存 + Cubist 快速精调）
   - v8：3861s（Cubist 完整 HPO + 10-fold CV）
   - v9：11109s（全模型完整 HPO + 10-fold CV，约 3 小时）
